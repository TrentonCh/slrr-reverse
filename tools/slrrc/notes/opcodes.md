# TREE opcodes: reference for a compiler writer

Generated by `lib/gen_opcodes_md.py` from the table in `lib/opcodes.py` (semantics), the corpus `D:\SLRR-test` (counts) and `notes/opcode_checks.json` (proofs, written by `lib/check_opcodes.py`). Regenerate instead of editing.

Scope: all 2,993 class blobs of the install (9,772 trees, 647,650 nodes), of which 2,829 blobs carry build 0x24F9D. Counts are given as "all / build 0x24F9D".

## 1. Reading a node

A node on disk is `op:u8, line:u16[, imm:u32]`.

- `op` indexes the 48-entry table `kTreeOpFlags` (`engine/include/tree_op_flags.inc`). The table value is the 16-bit opcode the VM dispatches on; its low byte repeats the index and its high nibble is the immediate class: 0 none, 1 u32, 2 float bits, 4 utf8 index. The node is 7 bytes when the nibble is 1, 2 or 4 and 3 bytes otherwise. At load the VM expands every node to an 8-byte record `{opcode:u16, line:u16, imm:u32}`; the PC strides 8, so every jump offset counts nodes, not bytes.
- `line` (called `slot` in docs/ENGINE.md) is the source line the compiler had reached when it built the node. The VM copies it to `jvm+0x70` before every instruction, for error messages. Proof: over the 2,819 pairs every node line lies inside the source file, and the literal or member name a node carries stands on that line for 183,579 of 183,620 such nodes; the rest sit in 15 stale pairs (`notes/corpus.md`).
- `imm` is, depending on the opcode, a constant pool index, a local index, a count, a signed jump offset, a literal value or the expression kind of `expr` / `stmt`.

The code is postfix: operands first, operator after. There are two stores per frame. The **operand stack** holds values and variables (a variable is a reference to a local, a field or an array element and stays assignable). The **locals** are a list: `this` at index 0 in instance methods, then the parameters in reverse order (the last parameter has the lowest index), then one entry per `declare`, removed again by `release` at the end of its scope. The fifth word of a method row is the high-water mark of that list.

Three kinds of node are not executed on their own: **carriers** (operand of the node before them: literal, type, class), the **init** marker behind a declaration, and **path segments** (consumed by the name walk of `path` and `call`). The disassembler indents them.

### What each opcode does

**0x0000 `fatal0`** (op 0, not emitted). Raises "fatal script error" and leaves the PC where it is (case map entry 0). Never emitted.

**0x1001 `local`** (op 1, executed or path segment). Push the variable locals[imm] itself (a reference, so the operand stays assignable). As a path segment (after 0x1011 or 0x0024) it is not executed: evalName takes locals[imm] as the current object. Locals are numbered: 0 = this (instance methods only), then the parameters in REVERSE order (the last parameter has the lowest index), then declared locals in order of declaration.

**0x1002 `declare`** (op 2, executed). Declare a local: append a new variable to the frame's locals; imm is the index it gets. The next node is always a 0x1006 type carrier whose utf8 is the declared type; the VM reads it and steps over it. When the node after the carrier is 0x002C the VM steps over that too and pushes the new variable as the target of the initialiser that follows (closed by 0x002D). (The VM would also accept a 0x402E node between 0x1002 and 0x1006; the compiler never emits one.)

**0x1003 `release`** (op 3, executed). Scope exit: remove the LAST variable from the frame's locals and release it. imm names the local that is expected to be on top (the VM does not read it). The operand stack is untouched.

**0x0004 `and_test`** (op 4, executed). Short-circuit test of "&&": pop, push back, test. True: skip the next node (always a 0x1014 jump) so that the right operand is evaluated; false: fall onto that jump, which leads past the right operand and its "expr land".

**0x0005 `or_test`** (op 5, executed). Short-circuit test of "||": as 0x0004 with the polarity reversed (false skips the jump, true takes it).

**0x1006 `type`** (op 6, carrier). Type carrier: a utf8 type descriptor ("I", "F", "Ljava.lang.String;", "[I", ...). Operand of 0x1002 (declared type) and of the expr/stmt tags new 0x1E, newarray 0x1F, instanceof 0x20 and cast 0x21. Reached on its own it does nothing.

**0x1007 `expr`** (op 7, executed). Expression node whose value is used; imm is the kind of expression (TAGS below).

**0x1008 `stmt`** (op 8, executed). The same expression kinds in statement position: the value is not wanted, so operators only discard their operands and assignments do not push.

**0x4009 `str`** (op 9, carrier). String literal carrier (after "expr literal"): utf8 index of the text. The VM pushes an interned java.lang.String.

**0x200A `float`** (op 10, carrier). Float literal carrier: imm is the IEEE single bit pattern.

**0x100B `int`** (op 11, carrier). Int literal carrier: imm is the value (type "I").

**0x000C `null`** (op 12, carrier). null literal carrier (an object-typed value with payload 0).

**0x100D `bool`** (op 13, carrier). Boolean literal carrier: the keywords true (imm 1) and false (imm 0). The VM boxes imm with another type descriptor than 0x100B (JVM global 0x7A2604 instead of 0x7A2608), otherwise it behaves as an int.

**0x100E `rid`** (op 14, carrier). Resource id literal carrier (pack:0xHEXr): pool index of a rid entry. The VM resolves pack file name + local id to the global id at run time and pushes it as an int.

**0x100F `op0f`** (op 15, not emitted). No case in the VM (default advance). Never emitted.

**0x0010 `end`** (op 16, executed). End of a field initialiser tree: marks the thread DONE and leaves the run loop. The value of the initialiser is what is left on the operand stack.

**0x1011 `path`** (op 17, executed). Name path: imm segment nodes follow. Executed, it walks them (Thread_evalName_fieldPath) and pushes the variable the path ends in. Directly after 0x0024 it is not executed; it is the count header of the call's name path. A 0x1019 class segment counts as one segment but stands for "ClassName." in front of the segment after it.

**0x4012 `name`** (op 18, path segment). Path segment by name (utf8). In a field path: the field of that name on the current object, looked up at run time (never legal as the first segment of a field path). In a call path: when the current object has a field of that name the walk goes on through it, otherwise it is the name of the method to call, resolved at run time from the argument types.

**0x0013 `fatal13`** (op 19, not emitted). Raises "fatal script error". Never emitted.

**0x1014 `jump`** (op 20, executed). Unconditional jump: continue at node (this index + imm); imm is signed, loops jump backwards.

**0x1015 `jump_false`** (op 21, executed). Pop a value and convert it to boolean (int/float non-zero, object non-null). False: jump to (this index + imm); true: next node.

**0x1016 `jump_true`** (op 22, executed). As 0x1015 with the polarity reversed.

**0x1017 `case`** (op 23, executed). switch dispatch: pop the case value, pop the subject, compare (==). Equal: both are released and the VM jumps to (this index + imm). Different: the subject is pushed back and the next node runs.

**0x0018 `pop`** (op 24, executed). Pop one operand and release it (the switch subject once no case matched).

**0x1019 `class`** (op 25, carrier). Class carrier (pool class entry): the "ClassName." prefix at the start of a name path, or the target of a cast (expr tag 0x21). Reached on its own it does nothing. (The pool also holds class entries for array types, named "[I", "[F" or "[java.lang.String": bracket plus element class without the L...; wrapper. They are the class of member refs such as array.length and never stand in a 0x1019 node.)

**0x101A `method`** (op 26, path segment). Method reference that ends a call path (pool member ref with a "(...)R" descriptor). evalName pops and releases one operand first (the argc box pushed by 0x1027; it is not needed because the descriptor is known), then resolves the method: through the cached slot when the ref's class is the class of the current object, otherwise by name and descriptor. The call itself then pops the arguments.

**0x101B `field`** (op 27, executed or path segment). Field reference (pool member ref with a type descriptor). Executed on its own it pushes the field variable of this (instance field) or of the class (static field). As a path segment it reads the field on the current object or class of the walk.

**0x401C `getfield`** (op 28, executed). Pop an object, push its field named by the utf8 (looked up at run time on the object's class). Used when the receiver is an expression rather than a name path: this.x, a[i].x, f().x, (cast).x.

**0x001D `superfield`** (op 29, not emitted). VM case "super.field" by utf8 name; the op has no immediate in the flags table, so it cannot work. Never emitted.

**0x101E `array_init`** (op 30, not emitted). VM case: pop imm values and build an array from them (array initialiser lists). Never emitted (the dialect census finds no initialiser list).

**0x101F `push_zeros`** (op 31, not emitted). VM case: push imm fresh int values of 0. Never emitted.

**0x0020 `index`** (op 32, executed). Array element: pop the array (top), pop the index (below it), push the element variable (assignable). So a[i] is compiled index first, array second.

**0x0021 `new_init`** (op 33, executed). Constructor call of "new T(args)": the object pushed by "expr new" lies under the arguments and the argc box; the VM calls <init> on it by name with the argument types found on the stack. The call consumes the arguments and the argc box; the object stays as the value of the new expression.

**0x0022 `this_init`** (op 34, executed). this(args): call <init> of the frame's own class on this. Always followed by "stmt ctor".

**0x0023 `super_init`** (op 35, executed). super(args): call <init> of the superclass on this (skipped when the class has no superclass). Every constructor with code holds exactly one this_init or super_init: where the source has neither this(...) nor super(...), the compiler emits "push_int 0; super_init; stmt ctor" itself.

**0x0024 `call`** (op 36, executed). Method call through a name path. The node after it is either a single 0x101A method segment or a 0x1011 count header followed by that many segments, the last of which names the method (0x101A or 0x4012). Arguments were pushed left to right, then the argc box (0x1027). The callee's return value is pushed by its 0x002B; a void method returns a dummy int 0, so every call leaves exactly one value, which the following "expr call" keeps or "stmt call" drops.

**0x4025 `call_on`** (op 37, executed). Method call on a computed receiver: pop the receiver object, then call the method named by the utf8 on its class (resolved at run time from the argument types under the argc box). Order on the stack: arguments, argc box, receiver.

**0x4026 `call_super`** (op 38, executed). super.name(args): call the method named by the utf8 starting the lookup at the superclass, on this.

**0x1027 `push_int`** (op 39, executed). Push a fresh int value imm. The compiler uses it only for the argument count box that precedes every call form (0x0021-0x0024, 0x4025, 0x4026).

**0x0028 `value`** (op 40, executed). Pop the operand through VMThread_popOperand and push it again: a variable reference becomes a detached copy of its value. Emitted after the expression of "return expr;" so that the value survives the release of the locals that follows.

**0x0029 `push_void`** (op 41, executed). Push a fresh int 0: the dummy return value of a void method ("return;" and the implicit return at the end of a non-constructor body). Always followed by the releases of the live locals and 0x002B.

**0x002A `ret`** (op 42, executed). Return without a value: destroy the frame and resume the caller after its call node. Emitted only in constructors, which return nothing; every other method leaves through 0x002B.

**0x002B `ret_value`** (op 43, executed). Return with a value: pop it, destroy the frame, push it on the caller's operand stack and resume the caller.

**0x002C `init`** (op 44, carrier). Marker "this declaration has an initialiser". Only ever found two nodes after a 0x1002 (behind its type carrier), where the VM consumes it.

**0x002D `store`** (op 45, executed). Initialiser store: pop the value (top), pop the variable below it (it must be a variable), assign with conversion to the variable's type. Closes "declare; type; init; <expression>".

**0x402E `op2e`** (op 46, not emitted). Optional node between 0x1002 and its type carrier (a utf8 the VM hands to the variable constructor). Never emitted.

**0x0000 `fatal47`** (op 47, not emitted). Maps to opcode 0 like op byte 0. Never emitted.

**0x00 `cond`**. Conditional: pop the else value (top), the then value, the condition; push the chosen one. Both branches are evaluated before the choice.

**0x01 `lor`**. Logical or of two already evaluated operands. With the 0x0005 / 0x1014 pair in front of the right operand this node is only reached when the left operand was false.

**0x02 `land`**. Logical and (see 0x0004).

**0x03 `bor`**. Bitwise or.

**0x04 `bxor`**. Bitwise exclusive or.

**0x05 `band`**. Bitwise and.

**0x06 `ne`**. Not equal.

**0x07 `eq`**. Equal (strings are interned, so == on strings compares text).

**0x08 `ge`**. Greater or equal.

**0x09 `le`**. Less or equal.

**0x0A `gt`**. Greater.

**0x0B `lt`**. Less.

**0x0C `tag0c`**. No body in the VM (default advance). Never emitted.

**0x0D `shr`**. Shift right.

**0x0E `shl`**. Shift left.

**0x0F `sub`**. Subtract.

**0x10 `add`**. Add; string concatenation when a side is a String.

**0x11 `mod`**. Remainder.

**0x12 `div`**. Divide.

**0x13 `mul`**. Multiply.

**0x14 `bnot`**. Bitwise complement.

**0x15 `lnot`**. Logical not.

**0x16 `neg`**. Unary minus. Negative literals are compiled as the positive literal followed by this node; nothing is folded.

**0x17 `postinc`**. Pop a variable; expr: push a copy of its value, then increment the variable; stmt: increment only.

**0x18 `postdec`**. As 0x17, decrement.

**0x19 `preinc`**. Pop a variable, increment it; expr: push a copy of the new value.

**0x1A `predec`**. As 0x19, decrement.

**0x1B `call`**. Marks the end of a method call (after the 0x101A / 0x4012 that ends a call path, or after 0x4025 / 0x4026). expr: nothing to do, the return value is on the stack; stmt: pop and release it.

**0x1C `literal`**. Literal: the next node is the carrier (0x4009 string, 0x200A float, 0x100B int, 0x100D true/false, 0x100E resource id, 0x000C null). expr: push the value; stmt: step over the carrier.

**0x1D `tag1d`**. No body in the VM (default advance). Never emitted.

**0x1E `new`**. Object creation: the next node is the 0x1006 type carrier, always a class descriptor "Lpackage.Name;"; the VM loads the class and pushes a new, uninitialised instance (both as expr and as stmt). The arguments, the argc box and 0x0021 follow.

**0x1F `newarray`**. Array creation: the next node is the 0x1006 carrier of the ARRAY type ("[I", "[F", "[Ljava.lang.String;"); pop one size per "[" (the VM rejects more than one dimension), push the array.

**0x20 `instanceof`**. Pop an object; the next node is the 0x1006 carrier of the class descriptor ("Lpackage.Name;"); push int 1 when the object's class inherits from it, else 0 (null gives 0).

**0x21 `cast`**. Cast: pop a value, convert it to the type named by the next node and push it. The carrier is a 0x1006 descriptor for a primitive type (only "I" and "F" occur) and a 0x1019 class entry for a class type; no cast to an array type occurs. "cannot cast" is a script error.

**0x22 `ctor`**. Marks the end of a this(...) / super(...) call. No body in the VM; only the stmt form occurs.

**0x23 `assign`**. Assignment: pop the destination variable (top; "stack access: value on top (instead of variable)" otherwise), pop the source value, assign with conversion to the destination type. expr pushes the source value. So the right-hand side is compiled first, the left-hand side second.

**0x24 `mul_assign`**. Compound assignment.

**0x25 `div_assign`**. Compound assignment.

**0x26 `mod_assign`**. Compound assignment. Never emitted in the corpus.

**0x27 `add_assign`**. Compound assignment (string append when the destination is a String).

**0x28 `sub_assign`**. Compound assignment.

**0x29 `tag29`**. Assignment kind the VM reports as unsupported. Never emitted.

**0x2A `tag2a`**. Assignment kind the VM reports as unsupported. Never emitted.

**0x2B `tag2b`**. Assignment kind the VM reports as unsupported. Never emitted.

## 4. Name paths

A **field path** is an executed `path n` followed by n segment nodes; it pushes the variable the path ends in. A **call path** follows a `call` node: either one `method` node, or a `path n` header (not executed) and n segments of which the last names the method. In both, a leading `class` node means "ClassName." and counts as a segment.
